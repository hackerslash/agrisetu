# AgriSetu — Design System

## Design Context

### Users
- **Vendors** (agri-input dealers/suppliers, often in semi-urban / rural India): manage gigs (offers), bid on farmer clusters, fulfil orders, track payments/escrow, view analytics. Frequently less tech-savvy; need clarity and confidence over density. Desktop-only portal.
- **Superadmins**: verify/approve/suspend vendors from a verification desk.

### Brand Personality
Warm, grounded, trustworthy, plainspoken. Three words: **warm, dependable, harvest**. The interface should feel like a well-made handbook for running an agri business — reassuring, not corporate or sterile. Emotional goal: calm confidence ("I know what to do next").

### Aesthetic Direction — "Harvest" (light mode)
Friendly and approachable, generous spacing, soft rounded forms, humanist type, big targets, plain language. Not a dense trading terminal; not a generic SaaS dashboard. Warm paper surfaces, real color variety (not one-hue mud), large readable numbers, clear next actions.

Anti-references: cyan-on-dark SaaS, purple gradients, identical icon-card grids, rainbow status pills, gradient text, side-stripe accent borders.

### Color (OKLCH, three distinct roles + warm neutrals)
- **Leaf green** `--color-leaf-*` — primary / growth / positive. Buttons, active nav, success.
- **Clay / terracotta** `--color-clay-*` — secondary / human / earthy. Secondary actions, warm highlights.
- **Harvest gold** `--color-gold-*` — accent / energy / attention. Sparingly: highlights, "needs you" emphasis.
- Warm neutrals tinted toward hue ~70–80: `--color-paper` (app bg), `--color-surface` (cards), `--color-sunk` (inset), `--color-line` (borders), `--color-ink / ink-soft / ink-faint` (text).
- Semantic: `success / warning / danger / info` each with a `-bg` tint. Status uses a dot + label, never a rainbow of solid pills.
- Never pure #000 / #fff. 60-30-10 weight: neutral surfaces / secondary text+borders / rare accent.

### Typography
- **Display / headings**: Bricolage Grotesque (characterful, warm, credible).
- **Body / UI / data**: Hanken Grotesk (humanist, highly legible; tabular figures for numbers via `.tnum`).
- Fixed rem scale for app UI. Strong hierarchy (≥1.25 ratio). Body capped ~70ch.

### Design Principles
1. **Clarity over density** — fewer, bigger, well-spaced elements; one obvious next action per view.
2. **Warmth with backbone** — soft and friendly, but confident structure and real hierarchy.
3. **Color with meaning** — three hues with fixed roles; accents are rare and earn attention.
4. **Tokens, not hex** — everything routes through CSS variables / Tailwind utilities; no inline hardcoded colors.
5. **Plain language** — labels and empty states teach; numbers are legible and tabular.

## Implementation Notes
- Tailwind v4 `@theme` in `app/globals.css` is the single source of truth for tokens.
- Brand utilities: `bg-leaf-600`, `text-ink`, `border-line`, `bg-clay-500`, `bg-gold-400`, `bg-paper`, `bg-surface`, etc.
- Reusable component classes in `@layer components`: `.card`, `.btn` (`.btn-primary/.btn-secondary/.btn-ghost/.btn-danger`), `.field`, `.eyebrow`, `.pill`, `.skeleton`. Prefer these + a `<Button>` component over re-styling per page.
- Fonts wired in `app/layout.tsx` via `next/font/google` (Bricolage_Grotesque, Hanken_Grotesk).
